# Schema Validation Checklist for Zio Iran

این فایل برای بررسی داده‌های ساختاریافته قبل از انتشار روی zioiran.com آماده شده است.

## ابزارهای بررسی

| ابزار | کاربرد |
|---|---|
| Google Rich Results Test | بررسی امکان نمایش rich result |
| Schema.org Validator | بررسی ساختار کلی JSON-LD |
| Search Console URL Inspection | بررسی بعد از انتشار |
| Rank Math Schema Preview | کنترل داخل وردپرس، اگر فعال باشد |

## چک‌لیست عمومی

| مورد | وضعیت |
|---|---|
| JSON معتبر است و خطای syntax ندارد | ☐ |
| URLها واقعی و قابل باز شدن هستند | ☐ |
| logo واقعی و درست است | ☐ |
| تصویر محصول واقعی و مرتبط است | ☐ |
| نام برند یکدست `Zio Iran` است | ☐ |
| نام فارسی `زیو ایران` در جای مناسب آمده است | ☐ |
| قیمت جعلی وارد نشده است | ☐ |
| امتیاز و review جعلی وارد نشده است | ☐ |
| availability با وضعیت واقعی کالا هماهنگ است | ☐ |
| FAQ داخل schema با FAQ قابل مشاهده در صفحه یکی است | ☐ |

## Organization Schema

- فقط روی صفحه اصلی یا درباره ما کافی است.
- `sameAs` فقط شامل لینک‌های واقعی و رسمی باشد.
- اگر لوگو URL ثابت ندارد، قبل از انتشار اصلاح شود.
- توضیح برند باید آموزشی و غیراغراق‌آمیز باشد.

## Product Schema

- برای هر دسته یا محصول، نام محصول باید با صفحه هماهنگ باشد.
- تصویر باید همان محصول یا دسته را نشان دهد.
- قیمت فقط وقتی درج شود که قیمت واقعی و قابل نمایش در صفحه وجود دارد.
- اگر صفحه دسته است و محصول واحد نیست، می‌توان از schema سبک‌تر یا ItemList استفاده کرد.

## FAQ Schema

- سوال و جواب‌ها باید در متن صفحه هم قابل مشاهده باشند.
- جواب‌ها کوتاه، مستقیم و بدون تبلیغ شدید باشند.
- سوالات تکراری در چند صفحه بهتر است کمی متناسب با همان صفحه بازنویسی شوند.

## HowTo Schema

- فقط برای راهنمای اندازه‌گیری یا مراحل واقعی استفاده شود.
- هر مرحله باید در متن صفحه هم دیده شود.
- ابزارهای لازم مثل متر و یادداشت ابعاد می‌توانند در متن ذکر شوند.

## خطاهای خطرناک

- گذاشتن review rating بدون review واقعی
- استفاده از قیمت ساختگی برای همه محصولات
- قرار دادن FAQ schema بدون نمایش FAQ در صفحه
- استفاده از Organization schema با لینک‌های شبکه اجتماعی غیررسمی
- استفاده از کلمات تبلیغاتی سنگین داخل description
